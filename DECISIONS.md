# Decisions and deviations from the plans

One line per decision, with rationale.

## Phase 1

- **Python 3.11.9 venv (`.venv`)** although 3.14 is the system default: satisfies "3.11+" and avoids wheel gaps for pinned deps (Phase 2 tooling too).
- **`.env` loaded by a 15-line stdlib loader (`phase1.config.load_dotenv`)** instead of adding `python-dotenv`: keeps the pinned dependency list to what the plan specifies; existing env vars take precedence.
- **Stage 1 samples instead of enumerating code search.** Docs (checked 2026-10-28): 10 req/min, 1,000 results/query, default branch only, files < 384 KB, `filename:` is the only qualifier allowed without a search term. Probe: ~945k CLAUDE.md and ~1.13M AGENTS.md files indexed, so exhaustive `size:` partitioning would need >2,000 partitions (~33 h). Instead: a seeded, prefix-stable random sample of narrow `size:` windows (log-uniform start in [100, 100000] bytes, width = 0.05% of start) per filename, fetching *every* hit in each window (halving any window over the cap). This is a random cluster sample by file size, not a census; log-uniform starts over-weight large files relative to the population. Raise `search_windows_per_filename` to extend it.
- **Repo metadata via batched GraphQL (50 repos/query)** instead of one REST call per repo: the sample yields thousands of unique repos, and per-repo REST would exhaust the 5,000/h core limit. Commit counts per context file still use the REST commits API with `path` (as planned): `per_page=1`, count = `rel="last"` page number, oldest commit = that last page.
- **`as_of_date` in config** (2026-10-28) is the reference date for `min_days_since_file_created`, so the filter is reproducible.
- **Code search's `filename:` is case-insensitive**; only exact-case basenames (`CLAUDE.md`, `AGENTS.md`) are kept. Nested context files (e.g. `packages/web/CLAUDE.md`) are kept.
- **Bare, single-branch, no-tags clones** (`git clone --bare --single-branch --branch <default>`): history-only analysis needs no checkout, which avoids Windows path problems and halves disk use.
- **Overlapping `--follow` chains** (e.g. CLAUDE.md renamed to AGENTS.md, then CLAUDE.md re-created as `@AGENTS.md`): each (commit, path-at-commit) version is analyzed once, claimed by the longest chain; others are marked `duplicate_of_other_chain`.
- **Aliases** are detected per version: a symlink, or a file whose only non-heading lines are `@path` imports. Alias versions are not extracted; an alias's target is analyzed even if code search did not return it.
- **References are resolved relative to the repo root or the context file's directory** (nested context files often use package-relative paths).
- **Extra extraction rules beyond the plan's minimum** (all heuristic, recall-oriented, since a reference must resolve at S to become a candidate): markdown link targets, `@path` imports, directory trees in code fences rebuilt into full paths, `pnpm/yarn <script>` without `run`, `npm test/start`, `make -C dir`. `make`/`just` are only extracted from code spans/fences (prose has "make sure", "just run").
- **SCRIPT resolution scope:** root `package.json` or the one in the context file's directory; commands with workspace flags (`--filter`, `-w`, `--workspace`, ...) resolve against any `package.json` (excluding `node_modules`). Make targets support `%` pattern rules.
- **IDENT resolution excludes** all markdown/mdx/rst, `.mdc`, `.cursorrules`, `.windsurfrules`, `docs/`/`doc/` at any depth, and lockfiles, so agent-rule files cannot resolve their own references. Dotted module paths also resolve if `a/b/c` or `a/b/c.py` exists. One `git grep -w -F -f <patterns>` per commit covers all identifiers.
- **TOOL `pip`:** has no lockfile, so it fails only when `uv.lock`/`poetry.lock` is present (plan's conflicting-lockfile rule). `uv pip ...` counts as uv.
- **Fix detection records `fix_kind`**: `reference_removed`, `line_changed` (reference still present), `file_deleted`, `file_became_alias`. If unfixed, `resolves_again_at_head` records whether the reference resolves again at HEAD (e.g. the path was re-created).
- **PATH rename destinations** come from an unrestricted `git diff --find-renames` of the cause commit, because a path-limited `git log` shows renames out of the pathspec as deletions.
- **Stage 5 allocation:** proportional to stratum (ref_type) size with a floor of `min_per_stratum` (10), quota left unfilled by the per-repo cap is topped up from the largest strata; each row carries `sampling_weight = N_h / n_h` so Stage 6 can weight category frequencies.
- **Permalink verification** fetches both the GitHub blob page and the raw file at the version commit, and checks that the line at `line_no` equals the sheet's `line_text`.
- **Excluded context-file locations (Stage 1):** files under directories named mirrors/vendor/third_party/node_modules/templates/examples/fixtures/testdata/i18n/translations/locales (`exclude_path_segments`) are copies or shipped artifacts, not instructions for the host repo's agents (e.g. `mirrors/repos/PostHog@posthog/.../AGENTS.md`). Excluded 529 of 11,305 sampled files; 358 repos still pass all filters (370 before).
- **Ranking uses the sum of commits over a repo's qualifying context files** (plan says "number of context-file commits"; sum chosen over max).
- **`data/raw/commits/` is gitignored** (kept on disk as the immutable cache): REST commit objects include commit-author emails, and the data-ethics rule is to store/republish only what the analysis needs. Search and GraphQL caches are committed.
- **Full clones, not partial (Stage 2 benchmark, `data/interim/clone_benchmark.csv`):** on 3 repos, historical `git show` took 0.41-0.44 s partial vs 0.02-0.03 s full, and `git grep` at an old commit 1.6-2.7 s vs 0.03-0.27 s, because `--filter=blob:none` fetches each missing blob lazily over the network (and pickaxe `-S` over a range would fetch every blob). Full bare clones of all 150 repos use 34 GB, which fits (242 GB free).
- **`versions.jsonl`, `references.jsonl`, `globs.jsonl` are gitignored** (64 MB+; regenerable from the clones by `phase1.history` / `phase1.extract`).
